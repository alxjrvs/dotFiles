# agent-vault.txt — the declared contents of the 1Password vault the Claude
# service account can read (`claude-agent`, or whatever `BOOM_vault` names).
#
# Checked by `op-agent audit agent-vault.txt`, wired as a `boom verify` step.
# Drift in EITHER direction fails: an item in the vault but not listed here is
# blast radius nobody reviewed, and an item listed here but absent from the
# vault means a consumer is about to break.
#
# WHY A FILE AND NOT A COMMENT. Two 1Password facts make membership the whole
# control surface, so it has to be enforceable rather than described:
#
#   1. Service-account vault access is IMMUTABLE after creation. 1Password:
#      "If you want to grant a service account access to additional vaults or
#      Environments … you'll need to create a new service account." Scope can
#      never be tightened in place — only the vault's CONTENTS can change.
#   2. This is an Individual/Family account, so there is no Activity Log and no
#      service-account usage report (both Business/Teams only). No per-item,
#      per-timestamp record of what the SA read exists, and that gap is
#      deliberately accepted (2026-08-19).
#
# So: an item added to this vault without a commit is exactly the event the
# missing audit log would have reported. This file is how it gets reported.
#
# RULES
#   - kebab-case only, `^[a-z0-9]+(-[a-z0-9]+)*$`. Every op:// ref is re-parsed
#     by `sh -c`, so a space word-splits and the resolve fails silently — the
#     bug that took down two MCP servers on 2026-07-25.
#   - One title per line. Trailing `#` comments are stripped.
#   - An entry earns its place by having a NAMED CONSUMER. If nothing resolves
#     it, it does not belong in a vault an agent can read.
